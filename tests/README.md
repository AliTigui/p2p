# Cross-crate test suites

Rust unit and integration tests live beside the code in each crate. This directory records the intended layout for future cross-crate suites:

- `unit/` — pure logic shared across crates (planned).
- `integration/` — storage, crypto, and app-facade integration tests (currently beside their crates).
- `networking/` — two-process and two-machine libp2p tests (two-instance tests currently in `crates/network/tests/` and `crates/chat/tests/`).
- `cryptography/` — known-answer and interop tests (planned).
- `security/` — fuzz targets and adversarial input tests (planned).

Implemented tests as of completed Milestone 13:

- `crates/core/`, `crates/identity/`, `crates/crypto/`, `crates/storage/`, `crates/messaging/`, `crates/groups/`, `crates/network/`, `crates/files/`, `crates/security/`, and `crates/chat/` contain their own unit and integration tests.
- `apps/desktop/src/model.rs` contains framework-independent GUI model tests; widget code is checked with `cargo check -p p2p-desktop --features gui`, and the native binary is built with `cargo build -p p2p-desktop --features native`. Milestone 11 added `.github/workflows/build.yml` plus `packaging/` scripts that produce locked release binaries, portable archives, Linux `.deb`, Windows `.msi`, macOS `.dmg`, and per-artifact SHA-256 sidecars; local verification commands and platform limits are recorded in `docs/BUILDING.md`.
- The controller acceptance suite is `crates/chat/tests/controller.rs`; it includes signed MLS setup, encrypted text/receipt delivery, offline queue, redial/resource-limit behaviour, multi-chunk encrypted file transfer, validation/scan/approval/cancel/release with a test-only scanner, encrypted attachment storage of a released file, and explicit quarantine deletion only on request. Milestone 9 adds three-controller Add/commit-ack/Welcome completion, Remove with epoch exclusion, self-Update with all-member acknowledgements, group text broadcast with all-member receipts, and non-admin denial. Milestone 10 adds default-channel initialization, admin-only channel create/rename/member policy, membership enforcement, channel text isolation inside one MLS group, restricted delivery to allowed members only, and policy acknowledgement state.
- `crates/groups/tests/mls_conversation.rs` covers three-member MLS Remove/Update epoch progression, excluded-member key inaccessibility, and stale-epoch rejection. `crates/chat/src/setup.rs` unit tests cover signed group-control frame round-trips, strict malformed/oversized/tampered rejection, and redacted `Debug`. `crates/chat/src/channel.rs` unit tests cover bounded `CHN1` text/policy round-trips, strict malformed/oversized rejection, member/text/name limits, and redacted `Debug`; `crates/messaging/src/envelope.rs` verifies the fixed `Channel` kind code.
- `crates/network/tests/direct_connect.rs`, `message_wire.rs`, `file_wire.rs`, and `resilience.rs` cover zero-bootstrap loopback connect, authenticated PeerId observance, MLS-envelope wire exchange, signed file frames over Noise, duplicate-dial rejection, connection caps, per-peer budget rejection, and bounded redial. Milestone 13 adds unit tests for all-off defaults, optional-config preconditions, direct-only address validation including `/p2p-circuit` rejection, bounded control-protocol codec round trips, redacted `ControlEvent` `Debug`, privacy-status defaults, NAT descriptions, and honest connection-state text.
- `crates/security` tests cover the `NoScanner`/default-denial policy, exact result categories, `ScanOutcome` construction, TXT/PNG/GIF structural validation and mismatch rejection, extension/name/size/count checks, and honest result descriptions. `crates/files` tests cover scan-before-integrity rejection, threat denial, validated-format policy gating, approval-required and cancellation behavior, in-memory released bytes, retained-by-default quarantine, explicit deletion after release or cancellation, and raw quarantine-byte scans showing no plaintext sentinel. `crates/storage` tests cover encrypted attachment blobs and metadata, cross-vault isolation, wrong-password/password-change behavior, digest rechecks, and explicit stored-attachment deletion. The desktop model tests cover the completed M10 and M13 milestone/security checklists, including group admin, member, pending-operation, active-channel, channel-policy, channel-access, and 24 honest privacy/status rows. The desktop app configures no independent scanner and no optional network feature by default; `IntegrityVerified`, structural validation, discovery, relay, NAT, identify, and control observations are never presented as clean, safe, trusted, or delivered.
- Milestone 12 tests cover cross-platform safe release names, an unraisable 64 MiB release cap, redacted `MessageEvent`/`SetupEvent`/`FileEvent` `Debug`, Unix symlink refusal for vault and quarantine directories, attachment deletion ordering before record removal, contact URI/query caps, identity envelope byte caps, and safer native save helpers where compiled. Windows ACL enforcement and secure erasure are intentionally not tested or claimed; non-Unix permission helpers remain no-ops and deletion is ordinary filesystem removal.
- Milestone 13 local verification: `cargo fmt --all -- --check`, `cargo clippy --locked --workspace --all-targets -- -D warnings`, `cargo check`/`cargo clippy` for `--features gui` and `--features native`, and `cargo build --locked -p p2p-desktop --features native` passed. The final serialized `cargo test --locked --workspace -- --test-threads=1` run passed **167 tests, 0 failures**: chat 31, core 4, crypto 8, desktop 13, files 14, groups 8, identity 27, messaging 15, network 25, security 11, storage 11; doc-test and empty lib/main groups reported 0 tests. A locked Linux x86_64 release build plus `packaging/linux/package.sh` produced `.tar.gz` and `.deb` artifacts; `dpkg-deb --info`, `dpkg-deb --contents`, `tar -tzf`, and both SHA-256 sidecar checks passed when run from `dist/`.
- External verification still pending: Windows/macOS artifact builds and installation, signing/notarization, visual GUI inspection, two-machine LAN/mDNS, two-machine NAT/relay, and configured Kademlia bootstrap tests. M13 does **not** test or claim strong anonymity, universal NAT traversal, auto-dialing of discovered peers, trust promotion from observations, or file transfer over relays.
